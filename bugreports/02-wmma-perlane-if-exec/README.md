# [AMDGPU] WMMA/SWMMAC builtins in lane-divergent control flow compile without a diagnostic, although the instruction ignores EXEC (gfx11, gfx12)

Suggested labels: `backend:AMDGPU`, `clang:codegen`.
Status: local draft, not filed upstream.

## Summary

A WMMA/SWMMAC instruction runs as if EXEC were all ones: it reads every lane's A, B, C (and sparse index) registers
and writes every lane's D registers, whatever the current EXEC mask is. This is the documented ISA rule (AMD RDNA 3/4
ISA guide) and was measured on gfx1201 across 20 dense and sparse forms (below).

The compiler accepts the builtin under a per-lane `if`, after a per-lane early `return`, and in a loop with a per-lane
trip count. It emits the `v_wmma` instruction inside the `s_and_saveexec` / `v_cmpx` region and assumes the
switched-off lanes are untouched. They are not: their operand registers are read (so they must hold meaningful
values) and their result registers are overwritten. No diagnostic, remark or uniform-EXEC guard is produced by any
compiler tried (ROCm 10.1, ROCm 10.2, Fedora clang 22.1.8; gfx1201 and gfx1200).

On a Radeon RX 9070 XT the stored results of such kernels differ from the full-wave model in up to 100 % of the
valid lanes, and the count changes from run to run. In a per-lane loop, the lanes that left the loop early receive
the result computed by the lanes that stayed (128 of 128 values).

The same shapes fail the same way on gfx1100 (RX 7900 XT) with different counts.

## Reproducer

```cpp
__global__ void bad_if(const v8h *A, const v8h *B, const v8f *C, v8f *D, int n) {
    const int l = __builtin_amdgcn_workitem_id_x();
    if (l < n) {
        D[l] = __builtin_amdgcn_wmma_f32_16x16x16_f16_w32_gfx12(A[l], B[l], C[l]);
    }
}
```

`repro.hip` also has `bad_early_return` (`if (l >= n) return;` before the WMMA), `bad_perlane_loop`
(`for (i = 0; i < trip[l]; ++i) c = WMMA(...)`) and `good_select` (the partial tile padded with a select; every lane
runs the WMMA).

Commands (device code only, no GPU needed). `<rocm>` is a ROCm install root:

```
<rocm>/bin/hipcc -x hip --cuda-device-only -S -O3 --offload-arch=gfx1201 repro.hip -o repro.s
/usr/bin/clang++ --rocm-path=<rocm> -nogpulib -x hip --cuda-device-only -S -O3 --offload-arch=gfx1201 repro.hip -o repro.s
```

Actual (ROCm 10.1, gfx1201, -O3; the same shape in every compiler of the matrix): the WMMA sits between the mask write
and the mask restore.

```
bad_if:
	...
	s_and_saveexec_b32 s2, vcc_lo
	s_cbranch_execz .LBB0_2
	...
	v_wmma_f32_16x16x16_f16 v[0:7], v[8:11], v[12:15], v[0:7]
```

`bad_perlane_loop` has `v_cmpx_lt_i32_e32 0, v14` at the loop entry and the `v_wmma` inside the masked loop. Fedora
clang 22.1.8 emits the same `v_cmp_gt_i32_e32` + `s_and_saveexec_b32` sequence for `bad_if` and `bad_early_return`.
In `good_select` the only masked region guards a load; the `v_wmma` follows the mask restore (`s_or_b32 exec_lo, exec_lo, s8`).

Expected: either a diagnostic for a WMMA/SWMMAC that is control-dependent on a lane-varying condition, or code that
does not depend on EXEC for the instruction (see "Suggested fix direction").

## Hardware evidence (RX 9070 XT, gfx1201)

Measured with the study's equivalent kernels (`k_ifload`, `k_early`, `k_loop`, `k_select`, `k_sink`, `k_uniform`);
same shapes as `repro.hip`, which was not run on a GPU in this CPU-only batch. Valid lanes are `lane < n`. The
reference is the CPU model of all lanes' operands as they sit in memory (what the programmer of a partly filled tile
means). The ROCm 10.1 runs used LACT profile "Testing" (stock core clock and voltage, 1258 MHz memory, 317 W cap with a
1.2x regulator mod), and the 2026-11-26 ROCm 10.2 follow-up used the overclocked profile (+150 MHz core, -50 mV, 1409 MHz
memory request, 374 W cap with the 1.2x mod); correctness counts do not depend on the clock.

Hardware rule (inline assembly, EXEC set around one instruction, D preset to a sentinel, 7 masks including EXEC = 0,
each launch run twice):

| Instruction | Results equal to the full-EXEC result | Switched-off lanes' D written |
|---|---|---|
| `v_wmma_f32_16x16x16_f16` | 256 of 256 for every mask | all (128, 128, 128, 192, 248, 256 for the 6 partial masks) |
| `v_wmma_f32_16x16x16_fp8_fp8` | 256 of 256 | all |
| `v_wmma_i32_16x16x16_iu8` | 256 of 256 | all |
| `v_wmma_f16_16x16x16_f16` (16-bit accumulator) | 128 of 128 | all |
| `v_swmmac_f32_16x16x32_f16` (sparse) | 256 of 256 | all |
| `v_dot4_f32_fp8_fp8`, `v_dot2_f32_f16` (controls) | only the enabled lanes' words | none |

All 20 forms tried (11 dense, 9 sparse: FP16, BF16, FP8/BF8 mixes, 8-bit and 4-bit integer, 16-bit accumulators) read
and write every lane whatever EXEC says, in wave32 and wave64, and take the same time to the cycle with EXEC full or
only lane 0 (16.000 cycles for the 16-bit-input forms, 8.000 for the 8-bit and 4-bit forms).

Compiler output on the card (ROCm 10.1 -O3 and ROCm 10.2 -O3 and -O1 print the same wrong counts; `bad_if` =
`k_ifload`, `bad_early_return` = `k_early`):

| n (valid lanes) | stored results that differ, `bad_if` and `bad_early_return` | Deterministic over 3 runs |
|---:|---|---|
| 8 | 64 of 64 | no |
| 16 | 128 of 128 (120 of 128 for `bad_if` in one ROCm 10.1 repeat) | no |
| 20 | 144 of 160 (140 for `bad_early_return` in the same repeat) | no |
| 31 | 23 of 248 | no |
| 32 (all lanes valid, control) | 0 of 256 | yes |

| Source shape | Result |
|---|---|
| `bad_perlane_loop` (lanes 0-15 two trips, 16-31 one) | lanes 16-31 are overwritten with the stale-operand result of the two-trip computation in 128 of 128 values; lanes 0-15 differ from "all lanes run 2" in 126 of 128 (ROCm 10.2) and equal the stale-operand model in 128 of 128 (ROCm 10.1); repeatable |
| `good_select` (padding by select) | 0 of 256 wrong |
| wave-uniform early return (`blockIdx` bound) | 0 of 256 wrong |
| operands loaded by all lanes, result stored under `if (l < n)` (`k_sink`) | 0 wrong for n = 8, 16, 20, 31 (the compiler leaves the WMMA before the mask) |
| loop with the same trip count in every lane | 0 of 256 wrong |

RDNA 3 (RX 7900 XT, gfx1100; ROCm 10.1 and 10.2, system clang 20): `ifload` 32 of 64 wrong (n = 8), 0 of 128 (n = 16),
24 of 160 (n = 20), 15 of 248 (n = 31); per-lane loop 128 of 256; select padding, wave-uniform return and uniform loop 0.
On gfx11 each half of the wave computes its own output rows from its own lanes' copies, so n = 16 happens to be right.

## Workaround

Make every lane execute the instruction and pad with a select; keep loop bounds and early exits wave-uniform:

```cpp
const v8h zero = {};
const v8h a = (l & 15) < n ? A[l] : zero;   // every lane runs the WMMA
D[l] = WMMA(a, B[l], C[l]);                 // store under `if (l < n)` afterwards if needed
```

For loops, run the maximum trip count in every lane (`__builtin_amdgcn_readfirstlane` of a wave maximum, or a bound
that depends only on `blockIdx`) and zero-pad the operands of lanes that have no work.

## Suggested fix direction

The choice is the maintainers'. Options, in increasing effort:
1. Document the rule in the AMDGPU usage notes and the clang builtin documentation (EXEC is ignored; operands of
   inactive lanes are read, results of inactive lanes are written).
2. Diagnose a WMMA/SWMMAC intrinsic whose basic block is control-dependent on a divergent branch (the IR has a
   uniformity analysis that knows which branches are divergent). A warning would catch all three shapes above.
3. Make the lowering safe: a WMMA under a partial mask clobbers inactive lanes' result registers and reads inactive
   lanes' operand registers, so the allocator would have to treat the result registers as written in all lanes and
   keep the operands defined in all lanes.

## Run the checks locally (CPU only)

```
bash verify_cpu.sh [--out DIR]
```

Overrides: `ROCM_101`, `ROCM_102`, `FEDORA_CXX`, `FEDORA_CLANG`. Deliberate breaks (a break must turn the detector
RED or be flagged; the untouched listing must be GREEN). Last run:

- original: bad_if=1 (GREEN means detected), good_select=0 (GREEN means clean)
- break 1, WMMA of bad_if moved before the mask write: bad_if=0 (RED expected: 0)
- break 2, WMMA injected after the mask write in good_select: good_select=1 (flagged expected: 1)
- restored original: bad_if=1, good_select=0 (GREEN expected: 1 and 0)
- IR output with the WMMA hoisted out of the mask: FileCheck BAD fails (RED, as expected)

The scanner follows one function at a time: a WMMA in a non-inlined callee that is called under a partial mask is not
reported.
